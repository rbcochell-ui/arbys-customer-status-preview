# Arby's equipment status - design preview

The root page is a static visual example using invented store information. It does not read FORM.com, Tableau, SharePoint, work orders, or any live request. The Inactive link button demonstrates the intended appearance; it does not revoke access to this public demo.

The repository also contains an encrypted customer viewer at `track.html`. It can show a limited set of verified Thirsty work orders and label later project steps **Not confirmed**. One pilot customer link is already issued. Its opaque handle remains pinned to the original encrypted file in this public repository. The root page remains the invented preview when opened without a project link.

New project handles read encrypted status from the separate private-source, public-Pages site at `https://rbcochell-ui.github.io/arbys-customer-progress-pages/data/`. The customer link format stays `track.html?p=<opaque handle>#k=<private key>`. The viewer sends only the handle in a same-origin status request; the key stays in the URL fragment. If a new file is unavailable or revoked, the viewer shows the generic unavailable state. It does not try a legacy fallback. The source repository for new statuses is private, but published ciphertext can be fetched by anyone. This route is not live for new customers until reviewed source, link issuance, and signed-out checks pass.

Do not commit customer information, source exports, recipient details, or a decryption key to this repository. Any real project file must be encrypted and issued only after source, recipient, and publication checks. The full project URL is a bearer link: anyone who receives it can open that project's status. Removing a new status from the current private-source Pages deployment can make that link unavailable after deployment and caches clear; it cannot erase a previously downloaded copy. The pilot ciphertext already exists in this repository's public Git history, so that pilot has a separate rotation boundary. The source must be refreshed and checked daily for the first release; the page warns when its last verified data is 24 hours old.
